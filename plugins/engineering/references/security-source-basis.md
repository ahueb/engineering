# Source basis for security-reviewer (maintainer reference)

Optional reading. Load this file only when rationale for the `security-reviewer` rules or the security exposure reference, or revalidation of them, is explicitly requested — not as part of an ordinary review.

## Sources

Entries are sources read in full text (or the sections named by the entry's claim). Preprints, vendor claims, and practitioner write-ups are marked.

### LLM vulnerability detection and review

- **S01** - Risse, Liu, and Böhme (2024, preprint), *Top Score on the Wrong Exam*. <https://arxiv.org/abs/2408.12986>. Establishes: all 151 truly vulnerable functions in the studied C datasets needed context from outside the function (other functions, arguments, rarely the runtime environment). Does not establish: that exposure or deployment context helps an LLM reviewer; environment-dependence was 0-3% of cases.
- **S02** - Xiong and Zhang (ISSTA 2026), *Sifting the Noise*. <https://arxiv.org/abs/2601.22952>. Establishes: removing cross-file navigation dropped F1 from 95.5 to 62.5, and giving the same files up front performed about like no context; the agent also wrongly dismissed 22% of real vulnerabilities (77-85% of weak-crypto/hash ones). Does not establish: results beyond one model and 50 post-cutoff alerts.
- **S03** - Yildiz et al. (ACL 2025), *JitVul*. <https://arxiv.org/abs/2503.03586>. Establishes: an agent with caller, callee, and definition lookup beat a fixed dump of related functions by 8-9%; the fixed dump sometimes did worse than no context. Does not establish: results for models other than GPT-4o and 4o-mini.
- **S04** - Guo et al. (ICML 2025), *RepoAudit*. <https://arxiv.org/abs/2501.18160>. Establishes: removing the path-feasibility check raised false positives by 245%; prompting with all relevant functions at once produced hallucinated bugs. Does not establish: behavior for bug classes beyond memory bugs.
- **S05** - Li et al. (2026, preprint), project-scale agent study. <https://arxiv.org/abs/2601.19239>. Establishes: 74% of one agent's C/C++ warnings were false when reported before validating the path; telling agents the project's own APIs raised recall to 90-96%. Does not establish: results for non-C/C++ code or non-frontier agents.
- **S06** - Thornton (2026, preprint, single author), adversarial comments. <https://arxiv.org/abs/2602.16741>. Establishes: misleading comments had no significant effect on 8 models, and an instruction to treat comments as untrusted cut induced misses by 71%. Does not establish: false-positive effects (only missed findings were measured); synthetic data, small numbers.
- **S07** - Lu et al. (2026, preprint), vulnerability reasoning. <https://arxiv.org/abs/2602.06687>. Establishes: 36.4% of correct verdicts rested on wrong reasoning; failure modes include ignoring existing checks and wrong trust-boundary assumptions. Does not establish: causes beyond the studied models; graded by an LLM.
- **S08** - Yu et al. (2026, preprint), *Security Code Review with LLMs*. <https://arxiv.org/abs/2401.16310>. Establishes: persona and project-name prompts had small, model-dependent effects, a CWE list helped one model and hurt another, and model-generated context misled. Does not establish: results outside real Gerrit reviews; absolute scores were low.
- **S09** - Zheng et al. (2023), personas in system prompts. <https://arxiv.org/abs/2311.10054>. Establishes: none of 162 personas significantly beat no persona. Does not establish: anything about security tasks; open models up to 72B on general Q&A.
- **S10** - Widyasari et al. (ICSE 2026), *VulTrial*. <https://arxiv.org/abs/2505.10961>. Establishes: multi-agent courtroom debate doubled fully correct pairs but raised the false-positive rate from 0.17 to 0.52 with equal precision. Does not establish: benefit over equal-compute baselines; GPT-4o only.
- **S11** - Jafarikhah et al. (SAC 2026), CVSS scoring from CVE text. <https://arxiv.org/abs/2512.06781>. Establishes: models predicted attack complexity no better than always guessing the common value and required privileges poorly. Does not establish: scoring from code; inputs were text descriptions.
- **S12** - Wunder et al. (IEEE S&P 2024), human CVSS rating study. <https://arxiv.org/abs/2308.15259>. Establishes: 196 professionals rated attack vector, user interaction, and scope inconsistently, and 68% changed their own rating later. Does not establish: CVSS v4 consistency (the study covers v3.1) or LLM rater behavior.

### Deployed agent systems and practitioner reports

- **S13** - Anthropic, *claude-code-security-review* (GitHub Action and `/security-review`), source (vendor). <https://github.com/anthropics/claude-code-security-review>. Establishes: documented prompt design, including category exclusions (for example environment variables and CLI flags trusted) and a ">80% confident" report threshold. Does not establish: that the exclusions or the threshold are calibrated; no metrics are published.
- **S14** - Anthropic, *claude-security* plugin, source (vendor). <https://github.com/anthropics/claude-plugins-official/tree/main/plugins/claude-security>. Establishes: documented prompts for change scans that trace outward from changed lines, distrust comments, refute only with a located control, and mark pre-existing findings. Does not establish: measured effect of any step.
- **S15** - OpenAI, *Codex Security* skills, source (vendor). <https://github.com/openai/codex-security>. Establishes: documented prompts that work backward from sensitive consumers, stop expanding once boundaries are clear, rate severity from a fixed matrix, and name the minimal unresolved fact. Does not establish: performance; no results are published.
- **S16** - GitHub Security Lab (Mo and Stöckli, 2026), AI-powered scanning framework, with `seclab-taskflows`. <https://github.blog/security/how-to-scan-for-vulnerabilities-with-github-security-labs-open-source-ai-powered-framework/> and <https://github.com/GitHubSecurityLab/seclab-taskflows>. Establishes (practitioner write-up): threat model first, then suggest, then audit; 1,003 suggestions led to 139 confirmed and 91 after de-duplication; a prompt rule that concluding "no security issue" is acceptable. Does not establish: recall, or that the staging itself caused the precision.
- **S17** - Ermilov (Semgrep, 2025), *Can LLMs Detect IDORs?*. <https://semgrep.dev/blog/2025/can-llms-detect-idors-understanding-the-boundaries-of-ai-reasoning/>. Establishes (vendor, small n): Claude Code was right 68% when no check existed but 0 of 19 when the check was spread across files and 0 of 18 when middleware or the framework applied it implicitly. Does not establish: rates for current models.
- **S18** - Gaucher, Ermilov, and Gibler (Semgrep, 2025), *Finding vulnerabilities in modern web apps using Claude Code and OpenAI Codex*. <https://semgrep.dev/blog/2025/finding-vulnerabilities-in-modern-web-apps-using-claude-code-and-openai-codex/>. Establishes (vendor): 14-18% true positives over 445 hand-triaged findings and identical runs yielding 3, 6, and 11 findings. Does not establish: recall; the prompt asserted vulnerabilities existed and the models were older.
- **S19** - Agarwal (2026, preprint, single author), *Refute-or-Promote*. <https://arxiv.org/abs/2604.19049>. Establishes: a kill-mandate review removed 79% of candidates, but ten agents were unanimously wrong on one finding and a unanimously killed finding later became a CVE. Does not establish: an ablation or a general refutation rate.
- **S20** - Team Atlanta (2025), *ATLANTIS* technical report. <https://arxiv.org/abs/2509.14589>. Establishes: basic CodeQL found 20 of 57 reachable Java paths (45 of 57 with class-hierarchy analysis). Does not establish: reachability results for non-fuzzing reviewers; the system is fuzzing-centered.

### Standards and severity literature

- **S21** - FIRST, *CVSS v4.0 Specification* and *User Guide* (v1.2). <https://www.first.org/cvss/v4-0/cvss-v40-specification.pdf> and <https://www.first.org/cvss/v4-0/cvss-v40-user-guide.pdf>. Establishes: Base scores assume a reasonable worst case, severity is not risk, deployment details enter through Environmental metrics, and a library function never invoked scores 0 for that implementation. Does not establish: consistency of v4 ratings.
- **S22** - CERT/CC, *SSVC* documentation and decision data. <https://certcc.github.io/SSVC/>. Establishes: exposure (small, controlled, open) and technical impact as decision points, with unknown exposure treated as open. Does not establish: that the categories suit LLM reviewers.
- **S23** - Spring et al. (SEI, 2018), *Towards Improving CVSS*. <https://www.sei.cmu.edu/documents/574/2018_019_001_538372.pdf>. Establishes: CVSS's formula is unjustified, and the authors recommend lookup tables with categorical outputs, "never integers". Does not establish: v4 behavior (it predates v4).
- **S24** - Koscinski et al. (ACM CCS 2025), scoring-system agreement. <https://arxiv.org/abs/2508.13644>. Establishes: four major scoring systems agree with each other at about chance (kappa near 0). Does not establish: that a categorical table agrees better; Microsoft CVEs only.
- **S25** - Ponta, Plate, and Sabetta (ICSME 2018), static versus dynamic reachability of vulnerable dependencies. <https://arxiv.org/abs/1806.05893>. Establishes: static call analysis misses reflection and framework-invoked code, and deserialization gadgets are exploitable whether or not reached. Does not establish: rates outside Java dependencies.
- **S26** - OWASP, *Application Security Verification Standard 5.0.0* (2025). <https://github.com/OWASP/ASVS/tree/v5.0.0/5.0/en>. Establishes: normative statements that there is no scope for attackers, defaults must be secure for Internet use, and debug and test functionality stays out of production. Does not establish: LLM review practice; written for web applications.
- **S27** - Adkins et al. (2020), *Building Secure and Reliable Systems*, ch. 2, 6, 14. <https://google.github.io/building-secure-and-reliable-systems/raw/ch14.html>. Establishes (practitioner): check every call site of a changed guard, configuration is as critical as code, and build steps can be remote code execution by design. Does not establish: measured effect.

### Deployment exposure

- **S28** - Muralee et al. (USENIX Security 2023), *ARGUS*. <https://www.usenix.org/system/files/usenixsecurity23-muralee.pdf>. Establishes: 5,298 confirmed injection flows across 2.78M workflows, about 60% with low impact; severity depends on trigger, token, and secrets. Does not establish: job-level permission effects (not modeled).
- **S29** - GitHub Security Lab, *Keeping your GitHub Actions and workflows secure*, parts 1-4. <https://securitylab.github.com/resources/github-actions-preventing-pwn-requests/>. Establishes (vendor guidance): pwn requests, the list of untrusted contexts, that an `env:` indirection fixes shell injection, and that `workflow_run`, artifacts, and caches carry poisoning risk. Does not establish: prevalence.
- **S30** - GitHub Docs, *Secure use reference*, and changelog of 2023-02-02. <https://docs.github.com/en/actions/reference/security/secure-use>, <https://github.blog/changelog/2023-02-02-github-actions-updating-the-default-github_token-permissions-to-read-only/>. Establishes: self-hosted runner risk, a full SHA as the only immutable action reference, and a read-only default token for new repositories only. Does not establish: any particular repository's settings.
- **S31** - Docker, *Port publishing*, *Packet filtering and firewalls*, and *Engine security*. <https://docs.docker.com/engine/network/port-publishing/>, <https://docs.docker.com/engine/network/packet-filtering-firewalls/>, <https://docs.docker.com/engine/security/>. Establishes: ports publish on all interfaces by default and bypass ufw, hosts on the same L2 segment reach ports published to 127.0.0.1 before Docker 28.0, Swarm binds all interfaces, daemon control is effectively root. Does not establish: a host's firewall state.
- **S32** - Spahn et al. (RAID 2023), container-service honeypots. <https://sites.cs.ucsb.edu/~vigna/publications/2023_RAID_Honeypot.pdf>. Establishes: 20,455 exposed container and orchestration services, attacked within minutes, many exposures unintended by owners. Does not establish: current prevalence (2022 data).
- **S33** - Kubernetes, *RBAC good practices* and *Service*. <https://kubernetes.io/docs/concepts/security/rbac-good-practices/>, <https://kubernetes.io/docs/concepts/services-networking/service/>. Establishes: `list` or `watch` on secrets reveals them, pod creation grants secret access, `nodes/proxy` allows exec, and NodePort listens on all node IPs. Does not establish: cluster-specific policy.
- **S34** - AWS, *Instance metadata service configuration* and AWS Security Blog on defense in depth (MacCárthaigh, 2019). <https://docs.aws.amazon.com/AWSEC2/latest/UserGuide/configuring-instance-metadata-service.html>, <https://aws.amazon.com/blogs/security/defense-in-depth-open-firewalls-reverse-proxies-ssrf-vulnerabilities-ec2-instance-metadata-service/>. Establishes: IMDSv1 and v2 are both allowed by default, IMDSv2 uses hop limit 1 (2 for containers), account defaults apply only to new instances. Does not establish: any account's settings.
- **S35** - Novaes Neto, Madnick et al. (MIT CISL WP 2020-07), cloud SSRF case. <https://web.mit.edu/smadnick/www/wp/2020-07.pdf>. Establishes (working paper built on a complaint and press reports): SSRF through a misconfigured WAF reached the metadata address and yielded role credentials. Does not establish: first-hand incident facts.
- **S36** - Werkzeug, Jupyter Server, and Ray documentation. <https://werkzeug.palletsprojects.com/en/stable/debug/>, <https://jupyter-server.readthedocs.io/en/latest/operators/security.html>, <https://docs.ray.io/en/latest/ray-security/index.html>. Establishes: each exposes arbitrary code execution when reachable, the Werkzeug PIN is not a security control, and Ray provides no isolation. Does not establish: measured exposure rates (none found for Werkzeug debuggers).
- **S37** - MITRE, CWE-377, CWE-59, CWE-732. <https://cwe.mitre.org/data/definitions/377.html>, <https://cwe.mitre.org/data/definitions/59.html>, <https://cwe.mitre.org/data/definitions/732.html>. Establishes: developers assume a single-user system, so exploit likelihood is high where a host is shared. Does not establish: prevalence; none of the three is in the 2025 CWE Top 25.
- **S38** - Isbarov et al. (2026, preprint), *GitInject*. <https://arxiv.org/pdf/2606.09935>. Establishes: every tested provider fell to at least one attack in default configuration, and PR-branch instruction files load as operator-level instructions. Does not establish: an exhaustive attack set (11 attacks).
- **S39** - GitHub Docs, *Managing GitHub Actions settings for a repository* (fork pull-request workflows). <https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/enabling-features-for-your-repository/managing-github-actions-settings-for-a-repository>. Establishes: `pull_request_target` workflows run in the base context and always run regardless of fork approval settings. Does not establish: approval behavior for `workflow_run` or `issue_comment` (not stated).
- **S40** - Redis, `redis.conf` for 7.0. <https://raw.githubusercontent.com/redis/redis/7.0/redis.conf>. Establishes: `enable-protected-configs`, `enable-module-command`, and `enable-debug-command` default to `no`. Does not establish: the configuration of any deployed instance.

## Rules and their basis

| Rule | Basis | Strength |
|---|---|---|
| Exposure-first, bounded tracing outward from the change, with a stopping rule; no repository survey or bulk context dump | S01, S02, S03, S04, S14, S15, S21, S22 | empirical (lookup beats bulk) + documented behavior |
| Caller tracing through config-defined entry points; "no caller found" is weak evidence; deserialization and config-only flaws not downgraded for lack of a caller | S20, S25, S27, S14, S15 | empirical + normative |
| Widening changes are security changes (new caller, bind, port, role, trigger, removed check) | S14, S15, S27 | documented behavior + convention |
| Out-of-repository settings are UNDETERMINED, never safe | S30, S31, S34, S32, S39, S15 | documented behavior |
| Attacker positions as a filter; name the gain beyond held access | S14, S15, S16, S07 | convention + documented behavior |
| Implicit-control search before claiming a missing check | S17, S05, S16, S07 | empirical |
| Refutation with a located, read control; comments are not controls | S04, S05, S06, S07, S14, S19 | empirical + documented behavior |
| Lower-confidence classes (crypto parameters, cookie or header policy, races, multi-step authorization) | S02, S06 | empirical, thin |

## Limits

No study validates exposure-aware prompting or the severity table for LLM reviewers; the table rests on human-practice standards, vendor agent prompts, and studies of other models and tasks. Static caller search under-approximates reachability, so a missing caller is weak evidence. Human CVSS raters disagree with each other and scoring systems disagree across systems, and categorical tables have not been shown to do better. Most measured numbers here are vendor claims, funnel ratios, preprints, or older models. Prevalence data come from public open-source code or vendor telemetry and may not match a given repository.
